# Порядок сборки и развёртывания

## 1. Подготовить каталог образа

Положить рядом Dockerfile, dognauts.patch, apply_frontend_changes.js. Скачать архив upstream-коммита:

```bash
curl -fL \
  https://github.com/jlon/starrocks-admin/archive/e8129b1444b86f6a2c87a5d08798cfde61c7d197.tar.gz \
  -o src.tar.gz
```

Git-клон, git-репозиторий, checkout, commit и `git apply` не нужны.

## 2. Собрать новый образ

```bash
docker build --pull \
  -t harbor.neoflex.ru/dognauts/starrocks-admin:1.0.0-dognauts.2 \
  .
```

Если базовые образы доступны только через зеркало Harbor, передать `NODE_IMAGE`, `RUST_IMAGE`, `RUNTIME_IMAGE` через `--build-arg`.

## 3. Проверить и опубликовать

Сначала локально запустить образ с UID 1001, `--read-only`, `--cap-drop ALL`, томами `/app/data` и `/app/logs`, как указано в README. Затем:

```bash
docker push harbor.neoflex.ru/dognauts/starrocks-admin:1.0.0-dognauts.2
```

## 4. Обновить чарт

В `values.yaml` изменить только `adminUi.image.tag`. `templates/admin-ui.yaml` не менять. Отдельно сверить VirtualService по документу `ИЗМЕНЕНИЯ-РОДИТЕЛЬСКОГО-ЧАРТА.md`.

## 5. Проверить шаблоны

```bash
helm lint .
helm template starrocks . -f values.yaml > /tmp/starrocks-rendered.yaml
```

Убедиться, что API-маршрут полного префикса Admin UI расположен раньше catch-all маршрута страницы.

## 6. Развернуть и проверить

Развернуть обычным для проекта способом. Убедиться, что provisioner завершил настройку и зарегистрировал кластер. При штатном входе через меню в DevTools → Network не должно быть запросов `/api/auth/platform-login`, `/api/auth/login`, `/api/auth/permissions`. Не запускать проверку старого `/api/auth/platform-login`: в новом образе такого endpoint нет.
