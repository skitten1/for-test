# Изменения родительского чарта

Код приложения меняется только в образе. В родительском чарте не нужно менять Deployment/provisioner.

1. `values.yaml`: после публикации нового образа поменять только `adminUi.image.tag` на `1.0.0-dognauts.2`. Остальные значения оставить как есть.
2. `templates/admin-ui.yaml`: не менять. Сохранить оба контейнера, provisioner, его локальный URL `127.0.0.1:8080/api`, Vault, PVC, securityContext и `APP_JWT_SECRET`. Переменные `APP_PLATFORM_AUTOLOGIN_USER`/`APP_PLATFORM_AUTOLOGIN_PASSWORD` основной контейнер нового образа не использует; их удаление — необязательная уборка, не требование для запуска. Переменные `APP_USER`/`APP_PASSWORD` provisioner не трогать.
3. VirtualService: это отдельный вопрос маршрутизации, не часть `admin-ui.yaml`. По сохранённому контексту ранее был общий маршрут `/project-api/api/` и отдельный маршрут страницы Admin UI. Новый frontend формирует API URL под полным префиксом Admin UI: `/project-api/<project>/<release>/starrocks/admin-ui/api/`. Если текущий VirtualService всё ещё не имеет отдельного API-маршрута под этим префиксом, его нужно добавить ПЕРЕД маршрутом страницы:

```yaml
- match:
    - uri:
        prefix: <полный существующий префикс Admin UI>/api/
  rewrite:
    uri: /api/
  route:
    - destination:
        host: starrocks-admin-ui
        port:
          number: 8080
```

`<полный существующий префикс Admin UI>` — это существующее Helm-выражение, которым строится путь страницы проекта; не подставлять буквальный текст. Существующий маршрут страницы оставить после API-маршрута.

До rollout проверь, что ext_authz получает исходный проектный путь до rewrite или имеет доверенный исходный путь. В истории уже фиксировалась ошибка извлечения `project_id` из глобального `/project-api/api/...` и из переписанного `/api/...`. Не отключать ext_authz.
